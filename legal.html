01 · Privacy policy

Who is responsible. ai-memory.net is the product site for Mnemosyne OS, operated by Guangdong Xinshiming Industrial Co., Ltd. (广东鑫室铭实业有限公司). For any question, request or complaint about this policy, use the contact page — it reaches the maintainer directly, which is a shorter path than any form letter.

This site has two halves, and they handle data differently. It is worth being precise about which half you are using.

  • The landing page and the documentation are static. Reading them creates no account, sets no cookie, and stores nothing in your browser beyond your theme and language choice. Nothing is submitted to us.
  • The hosted console needs an account. If you sign in — with GitHub or with an emailed one-time code — we store the email address you authenticate with, a password hash if you set a password, an avatar if you upload one, the API keys you create, and the memories you choose to save. That is the whole list.
  • Passwords are never stored in a recoverable form. They are hashed with PBKDF2-SHA256, 200,000 rounds, with a random per-account salt. We cannot read your password, and neither can anyone who takes a copy of the database.

Third-party components and where they run

  • GitHub OAuth — the optional sign-in path. If you use it, GitHub authenticates you and tells us your GitHub identity; GitHub's own privacy statement governs that step.
  • WorkBuddy Cloud SDK — an optional managed backend used for end-user authentication and managed Postgres. It is only functional on its registered release domain (mnemosyne-os.app.workbuddy.host). On ai-memory.net the SDK is present in the page but cannot establish a session; the UI says so rather than pretending otherwise.
  • Google Fonts and other CDNs are deliberately absent. Fonts are self-hosted so that loading this site does not leak your IP address to a font host — which is also why the page still renders correctly on networks where those hosts are unreachable.

Where the data physically is

The web server is hosted in a Google Cloud region in the United States. If you are in the European Union, the United Kingdom, or mainland China, using the hosted console therefore involves a cross-border transfer of the data you put into it. The engine itself is local-first — it writes to a SQLite file on your own machine and transfers nothing — so the usual answer is to run it yourself and keep the data local. That is not a workaround; it is the intended design.

Children

This site is a developer tool and is not directed at children. We do not knowingly hold personal data from anyone under 16. If you believe we do, write to us and we will delete it.

02 · What the server records, and for how long

Caddy writes a JSON access log for this domain. It is the only record of your visit, and it is the reason we can describe it here precisely instead of with adjectives.

  • Fields recorded: timestamp, IP address, request line, HTTP status code, response size, response duration, User-Agent, and — when your browser sends one — the Referer.
  • Retention: the log rotates at 10 MiB, keeps five files, and nothing older than 30 days is retained. When the oldest file ages out it is gone.
  • Purpose: two things only — aggregate visitor figures on the password-protected dashboard at /stats/, and security work: spotting scanners, breaking up brute-force attempts and rate-limiting abuse.
  • Never written to the log: Authorization headers, Cookie and Set-Cookie headers, and request bodies. Session tokens and passwords cannot appear in the log because they are never written to it.
  • Not used for: profiling, advertising, cross-site tracking, or training a model.

Server-side requests from the machine itself and from private address ranges are excluded from the visitor figures, so the numbers on that dashboard describe other people rather than our own health checks. Where a figure is derived from the log rather than observed directly, we would rather say so than let it read as something it is not.

03 · Cookies and local storage

  • No tracking cookies. This site sets none — for advertising, analytics, or anything else. There is no cookie banner because there is nothing to consent to.
  • One strictly necessary session cookie. If you sign in to the console, a cookie named mn_sid carries your session. It is HttpOnly (unreadable from JavaScript), SameSite=Lax, and Secure over HTTPS. It expires after 30 days of inactivity, and signing out clears it immediately.
  • HTTP Basic authentication on /stats/. The visitor dashboard is protected with the browser's built-in Basic auth. Your browser may offer to remember those credentials; that is a browser feature, not a cookie we set.
  • Local storage, preferences only. Two keys — mn-theme (dark or light) and mn-lang (English or Chinese). They stay in your browser, are never sent to the server, and are not readable across other websites.
  • Clearing everything is done from your browser's own settings. No request to us is needed, and nothing breaks if you do it.

04 · Your rights over your data

If you hold an account, you can export what the console stores about you from the dashboard, and you can revoke any API key yourself at any time. For a formal request under the GDPR, PIPL or a comparable regime, write through the contact page — we answer the request rather than redirecting you to a form.

  • Access and portability — export from the console, or ask us for a copy.
  • Rectification — edit any memory in the console; correct your profile in place.
  • Erasure — ask, and the account and its memories are deleted. This is a real deletion: memories live in a single SQLite file, and removing it removes them. Copies held in encrypted backups expire on the normal backup cycle.
  • Objection and restriction — name the processing you object to and we stop it.
  • Complaint — you may also complain to your local data protection authority. We would rather you told us first, but the right is yours either way.

02 · 服务器记录了什么，保留多久

Caddy 会为本域名写一份 JSON 访问日志。它是关于你访问的唯一记录，也正是我们能在这里 精确描述、而不必堆砌形容词的原因。

  • 记录字段：时间戳、IP 地址、请求行、HTTP 状态码、响应大小、响应耗时、 User-Agent，以及浏览器主动发送时的 Referer。
  • 保留期：日志按 10 MiB 轮转，保留 5 份，超过 30 天的内容一律不留。最旧的一份 到期即消失。
  • 用途：仅两件事 —— /stats/ 上密码保护的看板里的汇总访客数据， 以及安全工作：识别扫描器、阻断暴力破解、对滥用做限流。
  • 绝不写入日志：Authorization 头、Cookie 与 Set-Cookie 头、以及请求体。会话令牌与密码不可能出现在日志里，因为它们 根本不会被写进去。
  • 不用于：用户画像、广告、跨站跟踪、模型训练。

来自服务器本机与内网地址段的请求已被排除在访客统计之外，所以看板上的数字描述的是别人， 而不是我们自己的健康检查。凡是口径需从日志推导而非直接观测的指标，我们宁可在页面上标注 清楚，也不愿让它读起来像别的东西。

03 · Cookie 与本地存储

  • 没有跟踪 Cookie。一个都没有 —— 广告、统计、其他，都没有。也没有 Cookie 弹窗， 因为没有需要征得同意的东西。
  • 一个严格必要的会话 Cookie。你登录控制台后，名为 mn_sid 的 Cookie 承载你的会话。它是 HttpOnly（JavaScript 读不到）、SameSite=Lax、 HTTPS 下带 Secure。三十天不活动后失效，退出登录会立即清除。
  • /stats/ 使用 HTTP Basic 认证。访客看板由浏览器内置的 Basic 认证 保护。你的浏览器可能提出记住该凭据 —— 那是浏览器功能，不是我们设置的 Cookie。
  • 本地存储只存偏好。两个键：mn-theme（深色或浅色）与 mn-lang（中文或英文）。它们留在你的浏览器里，从不发送到服务器，也无法被 其他网站读取。
  • 清除全部内容在你的浏览器设置里完成即可，不需要向我们发起任何请求。清掉也不会 导致任何功能失效。
