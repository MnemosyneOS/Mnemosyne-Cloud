服务状态

Mnemosyne OS 服务可用性与历史事件。

Mnemosyne OS 跑在你的数据所在的地方，所以这里的"状态"指的是你自己节点的健康状况，而不是我们的可用性。三条命令足以覆盖，且全部可断网运行。

检查你自己的节点

# 进程体检：完整性、记录数、磁盘、向量后端、图边规模
mnemosyne --dir ./mem doctor --json

# 运行计数：写入、召回、节省的 token
mnemosyne --dir ./mem status --json

# 账本完整性 —— 若被改过，会指出是哪一条
mnemosyne --dir ./mem verify-integrity --json

recall_health 报什么

7.0.2 新增这一面是有具体原因的：记忆栈可以"活着"却正在变差。随会话时长退化的召回质量，在可用性检查里完全隐形，所以这一面报的是质量，不只是存活。

calls / empty_result_rate

召回被调用多少次，以及"没有相关记忆"这个诚实答案出现多少次。

floor_rejections

在被模型看到之前，有多少候选被相关性下限剔除。

latency p50 / max

检索延迟的中位与尾部。

channel_hits

五路召回通道里，实际贡献了分数的是哪几路。

sem_top1 / sem_background

候选余弦的 top1 与语料中位数 —— 用来发现阈值漂移的信号。

capsule_cache

胶囊缓存命中率，这正是上游提示缓存能持续命中的原因。

vector_ops / breaker

向量写入与删除的结果，以及熔断器状态与按原因分类的丢弃计数。

graph

边数、实体数、qualifier 覆盖率与回填状态。

健康的节点会报

  • chain_valid: true，且记录数与你预期一致。
  • 没有丢弃的向量写入。 熔断器是闭合的，dropped_unavailable 为 0。
  • 图边存在。 边数非零，说明知识图谱通道是真的在承担召回，而不是名义上存在。
  • 胶囊缓存命中率非零 —— 在跑过几次召回之后。

每个版本的更新记录（包括发现并修掉的缺陷）都在仓库的 CHANGELOG.md 里。把失效模式公开，本身就是产品的一部分。
