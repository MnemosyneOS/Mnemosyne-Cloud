# 迁移到 Cloudflare 的可行性判定与方案

判定时间：2026-09-22 03:30（北京时间）
判定依据：Cloudflare 官方文档（workers/platform/limits、pages、china-network）+ 你服务器实测数据。

---

## 一、一句话结论

**"全部迁移"做不到 —— 所以我没有执行。**

网站部分（静态页面）可以迁、而且值得迁；但**你真正在跑的东西（AI 记忆系统 + 登录后端）Cloudflare 上跑不了**。
而且实测下来，**迁移现在只能给你每月省约 0.5 美元**。

---

## 二、Cloudflare 是什么

它提供四类能力，**都不是"服务器"**：

| 能力 | 说明 |
|---|---|
| **CDN / 反向代理** | 把你的内容缓存在全球 300+ 节点，用户就近取；回源流量大幅减少 |
| **DNS 托管** | 免费权威 DNS（你现在用的是阿里云万网 DNS） |
| **安全** | 不限量 DDoS 防护、免费 SSL 证书、基础 WAF、免费版也有 Bot 对抗 |
| **边缘计算** | Workers（跑代码）、Pages（放静态站）、R2（对象存储）、D1（数据库） |

**它不提供**：VPS、Docker、常驻进程、本地持久磁盘。这三点决定了第三节的结论。

---

## 三、"终身免费"——精确回答

### 免费的部分（Free 套餐，无到期时间、无时间限制）

| 项目 | 免费额度 |
|---|---|
| CDN 带宽 | **不限量**（官方定价页写 "Unmetered"） |
| DNS / SSL 证书 | 不限量 |
| DDoS 防护 | 不限量 |
| **Pages 静态请求** | **免费且不限量**（官方原文：requests to static assets are free and unlimited） |
| Pages 构建 | 500 次/月，单站 20,000 个文件 |
| Workers | 10 万请求/天 |

### 免费**不**包含（这几点直接决定能不能迁）

| 你要的东西 | 免费版 | 事实 |
|---|---|---|
| Workers CPU 时间 | **10 毫秒/次** | 你的登录接口跑 PBKDF2 **20 万轮 ≈ 150 毫秒 CPU**，**超限 15 倍，跑不了** |
| Workers 内存 | 128 MB | 够呛 |
| Workers 个数 | **全账号只能 1 个** | 免费版硬限制 |
| 中国大陆节点 | **不含** | 官方明示：China Network 需 **Enterprise 套餐 + 单独订阅 + ICP 备案**，由京东云运营 |
| 运行容器 | 不含 | Containers 需 Workers 付费版（$5/月起）且**没有本地持久卷** |

### "终身"这个词要注意

Cloudflare 免费套餐**没有到期日**，但**没有合同保证、没有 SLA**——它随时可以改条款或调价（免费版和合同版的法律地位不同）。所以准确说法是"长期免费"，不是"法律上永远免费"。

## 四、逐项判定：什么能迁、什么不能

| 组件 | 现在跑在哪 | 能否迁到 Cloudflare | 判定依据 |
|---|---|---|---|
| 静态页面 + 资源（1.3 MB） | Caddy 伺服 | ✅ **可以**（Pages 免费不限量） | 纯静态，无状态 |
| 登录后端 `server.py` | GCP 127.0.0.1:8789 | ❌ **不行**（免费版） | 10ms CPU vs 需要 ~150ms；文件持久化需改写成 D1/KV |
| 联系表单 / 控制台数据 | 同上的 JSON 文件 | ❌ **不行** | 依赖本地持久磁盘 |
| **Mnemosyne 记忆系统（Docker + Qdrant）** | GCP 上的容器 | ❌ **根本不可能** | 需要**常驻进程 + 本地持久卷**，Cloudflare 不提供 VPS/Docker；Containers 也没有本地盘 |
| 访问统计看板生成器 | cron + Python | ⚠️ 需改写才能上 Workers | 读服务器日志文件，Cloudflare 上没有那个文件 |

**所以"全部迁移"这个前提不成立。** 记忆系统必须留在 GCP（或换到别的 VPS），它和网站之间没有替代关系。

**规模上来之后才值钱**（每人约 0.5–1 MB）：

## 六、你问的代理问题：中国用户用美国节点，算中国还是美国？

**算美国。** 地理定位只看 **IP**，不看人：

- 用户挂了美国节点 → 到达你服务器的源 IP 就是美国 IP → 面板记「美国」，反查城市也是美国城市。
- 这跟是否用 Cloudflare **无关**，只要用 IP 定位就是这个结果。换成香港节点就记「中国香港」。
- 没有办法从技术上知道"他本人其实在中国"——除非他自己登录了账号（那时可以按账号归属地统计，而不是按 IP）。

**⚠️ 一个更要紧的连带问题**：一旦你的站在 Cloudflare 后面，**Caddy 看到的全部是 Cloudflare 的机房 IP**。如果不管，你的统计面板会退化成"120 个访客全部来自美国 Cloudflare 机房"——**统计就废了**。这正是你要求"统计面板也正常统计"的关键点，我第六节给了具体修法。

## 七、可执行方案（分两阶段，按风险从低到高）

### 阶段 1：把网站挂到 Cloudflare 后面（推荐，风险低）

**做什么**：域名 NS 转到 Cloudflare，A 记录保持指向你 GCP 的 `35.227.140.175`（橙色云=开启代理）。

**效果**：静态资源缓存在边缘节点 → 回源请求大幅减少 → GCP 出站费用趋近于零。
**不改**：后端代码、登录逻辑、cookie、数据库——**一行代码都不用改**（因为同源没变）。

| 步骤 | 谁做 | 内容 |
|---|---|---|
| 1 | **我** | 给 Caddy 打补丁：启用 `trusted_proxies`（Cloudflare 官方 IP 段）+ `client_ip_headers CF-Connecting-IP`，让统计仍拿到真实访客 IP |
| 2 | **我** | 备份 Caddyfile、备份证书配置 |
| 3 | **你** | 注册 Cloudflare 账号（免费），添加域名 ai-memory.net |
| 4 | **你** | 到**阿里云域名控制台**把 NS 改成 Cloudflare 给的两个地址 |
| 5 | **我** | 配缓存规则（见下）、SSL 模式设为 Full (strict)、装 Cloudflare 源站证书 |
| 6 | **我** | 实测：主站、登录、GitHub 登录、留言、统计面板、备份按钮 全部回归 |

**缓存规则（阶段 1 会用到的）**：

```
/assets/fonts/*        -> 缓存 1 年（文件名是内容哈希，可以放心固化）
/assets/*.css|*.js     -> 缓存 4 小时（这几个文件名**不含哈希**，不能设 1 年）
/api/*  /auth/*  /stats/*  -> 绕过缓存（否则登录和统计会错乱）
其余（HTML）           -> 不缓存（源站已发 no-store）
```

> 顺带修掉你上次问的那个字体 404：现在 `*.css` 无 Cache-Control，浏览器自行启发式缓存，
> 重新本地化后字体改名 → 老访客短暂 404。上面这套规则一并解决。

**Caddy 补丁（我会准备好，验证后执行）**：

```caddyfile
{
    servers {
        trusted_proxies static 173.245.48.0/20 103.21.244.0/22 103.22.200.0/22 \
            103.31.4.0/22 141.101.64.0/18 108.162.192.0/18 190.93.240.0/20 \
            188.114.96.0/20 197.234.240.0/22 198.41.128.0/17 162.158.0.0/15 \
            104.16.0.0/13 104.24.0.0/14 172.64.0.0/13 131.0.72.0/22 \
            2400:cb00::/32 2606:4700::/32 2803:f800::/32 2405:b500::/32 \
            2405:8100::/32 2a06:98c0::/29 2c0f:f248::/32
        client_ip_headers CF-Connecting-IP
    }
}
```

这个补丁**可以提前打，没有副作用**：`trusted_proxies` 只在"发起连接的 IP 属于 Cloudflare"时才信任该头，所以在你真正接入 Cloudflare 之前，别人的伪造请求会被忽略，自动回退到真实地址。不会造成 IP 伪造或限流绕过。

### 阶段 2（可选，之后再说）：静态站搬到 Cloudflare Pages

把 HTML + assets 整个放到 Pages，GCP 就完全不管静态内容了；`/api/*` 用一个 Worker 继续转发到 GCP。

- 好处：静态部分延迟更低、GCP 出站彻底归零
- 代价：需要新增一个 Worker 路由来分流 `/api/*`；免费版 Worker 只有 1 个（够用，但没余量）
- **建议先做阶段 1，看效果再决定要不要阶段 2**——阶段 1 已经能拿走 95% 的收益

## 八、风险与回滚

| 风险 | 程度 | 说明 / 对策 |
|---|---|---|
| NS 切换期间解析短暂不一致 | 低 | 当前 TTL 600 秒，最坏 10 分钟内完成；两个地址我都保留原记录 |
| 漏掉 DNS 记录导致服务中断 | **极低** | 已实测枚举：全域名**只有 2 条 A 记录**（`@` 与 `www`），**没有 MX / TXT / AAAA / CAA、没有任何子域**。邮件不受影响 |
| 中国大陆访问变慢或不稳定 | **中** | 免费版**没有大陆节点**（需企业版+ICP）。大陆用户走香港/日本/新加坡节点。你现在在美西 Oregon，所以对大陆用户**可能反而更快**，但免费版路由不保证稳定 |
| 统计面板失真 | **高（若不处理）** | 已给修法（trusted_proxies）。**这是必须做的一步** |
| 免费版无 SLA / 无技术支持 | 中 | 免费版就是"尽力而为" |
| 未来想用大陆节点 | — | 必须企业版 + ICP 备案 + 京东云审核，不是"以后升级一下"那么简单 |

**回滚**：阿里云域名控制台把 NS 改回 `dns31.hichina.com / dns32.hichina.com` 即可，10 分钟内恢复；Caddyfile 有逐次备份，一条命令还原。**这两步都是分钟级、可逆的。**

## 十、我的建议（如果只允许一句话）

**先做阶段 1，但不必着急。** 它现在省的是每月几毛钱，真正的价值是**把将来的流量费封顶**（5000 人/天时省 $17–35/月）+ 免费拿到不限量 DDoS 防护。**记忆系统永远留在 GCP**——它才是这台机器的核心，网站只是它的门面。

同时，有一个**零风险、不用改 DNS、我立刻能做**的优化：给 `/assets/fonts/*` 加一年期 `immutable` 缓存头 + 给 `*.css` 加短缓存头。这能让**回访用户几乎不再重复下载资源**，在不动 Cloudflare 的前提下先把出站量降下来。要不要先做这个？
