## 二、指标之间的逻辑（三种互不重复的切法）

同一批 1,227 次请求，面板用三种**不同维度**切开，**彼此不可相加**：

1. **按来源**：本机 / 内网 165 + 外部 1,062 = 1,227
2. **按客户端类型**：爬虫·命令行 504（= 本机脚本 161 + 外部爬虫 343）；其余为浏览器
3. **按是否网页**：页面访问 PV 640 + 静态资源 587 = 1,227

另有三项是**全场统计**，不参与上述拆分：

- **独立访客 UV 137** = 真人 IP 97 + 脚本 IP 47（另有 7 个 IP 同时用过浏览器与脚本，两边都被计入，所以 97 + 47 = 144 > 137）
- **传输量 57.98 MB** = 所有响应体字节之和
- **平均响应 108.5 ms** = 所有请求耗时的算术平均

## 三、发现的口径瑕疵（建议修）

1. **PV 里混进了接口调用**：640 次「页面访问」中有 **286 次是 `/api/*` 接口**（如 `/api/auth/me` 117 次），真正网页只有 354 次。
2. **机房 IP 被当作真人访客**：
   - AWS 俄勒冈 3 个 IP（52.34.76.65 / 52.13.53.225 / 100.22.130.56）：各在 **10~15 秒内抓完整个页面的 24~32 个资源**，机器速度；
   - Google 爱荷华 136.113.87.34：2 小时内对首页探活 **32 次**，每次都只取 `/`，典型可用性监控；
   - 以上全部落进「真人访客」，`ip-api` 的 `hosting` 标志可以识别并标记。
3. **地理分布会被机房 IP 污染**：「覆盖 18 个国家/地区」数字正确，但 **US 的 404 次里大部分来自上述机房**，不代表真实美国用户；HK 的 505 次主要是你自己这条线路。

## 六、反爬虫建议（国际通用做法）

分三层，**不建议一刀切反爬**（官网的目标是能被搜到、能在微信 / Slack 里正确显示预览卡片）：

1. **声明意图（最省事、最标准）**：目前 **`robots.txt` 不存在**（日志中 5 次请求全 404），`sitemap.xml` 也没有，`favicon.ico` 也不存在（6 次 404）。应补上：放行首页 / blog / docs，禁止 `/api/`、`/stats/`、`/auth/`。
2. **选择性放行**：允许搜索引擎（Googlebot / Bingbot / Baiduspider）与社交预览机器人；是否放行 **GPTBot / CCBot / ClaudeBot** 这类 AI 训练爬虫是商业决策，需要在 robots.txt 里单独声明。
3. **真正的防护**：Cloudflare Bot Fight Mode / WAF、API 限流（已具备：登录 12 次/分、注册 6 次/10 分）、敏感路径 404（已具备）。

## 七、待修小缺陷

1. `robots.txt` / `sitemap.xml` / `favicon.ico` 均缺失，日志里持续产生 404。
2. **DM Mono 的 `.woff2` 有 7 次 404**：`/assets/fonts/981af9bb85bf.woff2`、`51016671455d.woff2`。当前 `dmm.css` 引用的是 `.woff`（文件存在、字体正常），那 7 次是对**旧文件名**的请求 —— 来自缓存了旧 CSS 的浏览器与爬虫。根因是本地化脚本重跑后字体文件改名，而 `assets/*.css` 没有显式 `Cache-Control`（浏览器启发式缓存）。
3. 面板的 PV 口径与机房 IP 标记可一并修正（见第三节）。
