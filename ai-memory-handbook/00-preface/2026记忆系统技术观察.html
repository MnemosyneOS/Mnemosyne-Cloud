2026 记忆系统技术观察 ​

本手册的第一章讨论「记忆为什么重要」，但那个问题在 2025 年就已经有共识了。真正需要证据的是另一组问题：2026 年这个领域的重心移动到哪里了、哪些能力在收敛、哪些落差在扩大。

本章不使用问卷数据。原因很直接：本书没有做问卷，而编造受访者比例是记忆领域最容易被识破的一类伪权威。替代方案是基于公开可复现信号观察——论文索引、官方文档、发布记录、公开仓库、定价页面。所有口径与截止时间都写明，任何读者可以用同样的检索式复算。

检索与抓取时间统一为 2026 年 10 月 30 日。涉及版本与价格的内容均以此日期为准，之后的变化请以官方页面为准。

一、核心发现 ​

发现一：学术侧的重心已经从「怎么存」转向「怎么抽象」。 ACL 2026 Findings 收录的综述把演进形式化为存储 → 反思 → 体验三阶段，并明确指出后两个阶段的方法论仍不成熟。这与工程侧的观察一致：写入与检索已有相对稳定的范式，而「把轨迹抽象成可复用经验」仍在探索期。

发现二：写入范式出现实质收敛。 单遍 ADD-only 提取被主要实现独立采纳。这意味着「不覆盖已有事实」成为行业下限共识，同时也意味着它不再是任何一家的差异化卖点。

发现三：能力声明与可验证性之间存在系统性落差。 几乎所有系统都能声明「支持记忆」，但能提供可复算基准、可定位篡改的审计、可验证删除的只是少数。落差不在功能有无，而在证据有无。

发现四：部署形态在向两端分化。 一端是绑定托管生态（云厂商运行时、托管上下文层），另一端是零依赖自托管。中间形态（需要自建图数据库或消息队列的自托管）在运维成本上被两端挤压。

发现五：检索粒度控制成为新的竞争点。 当基础召回能力趋同后，「让调用方精确控制取什么粒度」成为差异来源：有的系统把粒度做成显式参数，有的用两步披露控制注入成本。

发现六：中文与非英语场景仍显著欠覆盖。 主流基准以英语为中心，中文的专有名词、相对时间表达、近义表达在纯嵌入召回下失准明显，而针对这一问题的公开对照实验极少。

二、信号一：论文增长与结构分布 ​

用 arXiv API 的 search_query 做两次检索，可得到领域规模的一个下界估计。

text
https://export.arxiv.org/api/query?search_query=all:%22agent+memory%22&max_results=1
→ opensearch:totalResults = 600

https://export.arxiv.org/api/query?search_query=abs:%22memory%22+AND+abs:%22LLM+agent%22&max_results=1
→ opensearch:totalResults = 841

两个检索式都只匹配元数据字段，不检索全文，因此得到的是下界：大量以「long-term context」「persistent state」为题的论文不会被计入。任何人可在同一 URL 上复算，计数会随 arXiv 索引更新而变化，这是正常的。

更有信息量的不是总量，而是分布。综述给出的判断是：三阶段中「存储」已有成熟方法，「反思」有较多工作但缺少统一评价口径，「体验」的方法与度量都还稀缺。工程侧可以对应到一个具体结论：如果你今天要做的只是「记住并取回」，可用的成熟方案很多；如果你要做「从历史中提炼可迁移经验」，没有可直接照搬的方案。

这一点在选型时经常被混淆。厂商演示里的「越用越懂你」通常属于反思阶段的能力，而它的可靠性远低于存储阶段的能力。把两者当作同一件事评估，会系统性高估系统成熟度。

三、信号二：工程侧的能力收敛 ​

2026 年最值得记录的变化是写入范式的收敛。以 Mem0 为例，其官方研究页面在描述当前算法时列出四项：单遍 ADD-only 提取（一次 LLM 调用，只增不覆盖不删除，官方称提取速度约为原来的两倍，历史完整保留）、多信号检索（语义、关键词、实体三路并行打分融合）、时序推理（写入时完成分类）、记忆衰减（近期访问获得软性排序加权，闲置项随时间衰减，零检索延迟成本，且不删除不隐藏）。

这四项的组合与 Mnemosyne OS 的核心设计高度重合：后者同样采用单遍 ADD-only 提取、五路信号融合（语义 + BM25 + 实体图 + 时间 + 标签）、双时间轴与分层降级。两家在实现细节上差异明显，但在范式选择上已经趋同。

收敛对使用者是好事：范式稳定意味着迁移成本下降，也意味着可以用同一套评估方法比较不同实现。但它同时抬高了选型的门槛——当基础范式不再是区分点时，选型必须进入更细的维度：冲突如何裁决、删除如何证明、审计如何定位、成本如何随规模变化。

一个具体的对照可以说明这种细化。Mem0 的检索在官方口径下每次调用约 6,900 token，全上下文方案在 25,000 token 以上；这个差距决定了产品能否在高日活下定价。而 Mnemosyne 的差异点不在 token 数，而在预算控制的方式：recall(..., budget_tokens=N) 在预算约束下选择返回哪些记忆、以什么粒度返回，profile_card 的 max_tokens 是硬上限且按层丢弃而非句中截断。前者是「平均省」，后者是「上限可控」，适用场景不同。

四、信号三：能力声明与可验证性之间的落差 ​

把六个主要实现的公开材料并列，会看到一个规律：写入与检索的能力声明密度最高，审计与删除的证据密度最低。

能力声明普遍性可验证手段的普遍性
写入与召回高中（有 SDK 示例，少有成体系的自检脚本）
作用域隔离高低（少有跨租户读取测试）
审计中低（多为操作日志，非可定位的完整性证明）
删除高低（少有四层语义与 dry_run 预览）
基准可复现低低（多数只公布 headline 分数）

表 1　六类能力的声明密度与证据密度对比

这张表要读的是两列的差。差距越大，说明该能力的「可被相信」程度越低。审计与删除两行差距最大，恰好也是合规审查最先问的两件事。

一个可操作的判断是：向任何记忆系统索取三样东西——一条跨租户读取测试的脚本、一次 verify_integrity 的实际输出、一份级联删除的 dry_run 报告。三样都能当场给出的系统，其治理能力是可验证的；只能给出文档截图的，其治理能力是声明性的。

五、信号四：定价与部署形态的分化 ​

定价结构反映了各家对「谁承担运维」的判断。

Mem0 在 2026 年 10 月的公开定价只有两档：Free（无限终端用户；前 30 天每月 10,000 次 add / 1,000 次检索且模型调用由 Mem0 承担；自带 LLM key 则为 50,000 次 add / 10,000 次检索）与 Custom（按量报价，含图记忆、用户画像、记忆巩固、高级分析、SSO 与审计日志、SLA、本地部署）。这个结构说明其商业化重心在「需要治理与合规的大客户」，Free 层承担获客与开发者教育。

Mnemosyne OS 的 SaaS 走的是四档结构：Free（全部 52 个工具、冷层召回窗口 30 天、单命名空间、审计窗口 7 天）、Pro（$6.9/月或 ¥9.9/月，冷层永久、跨命名空间召回、审计历史不限）、Team（$19.9/席/月，多用户命名空间与团队策略）、Compliance Add-on（$9.9/月，仅月付仅加购）。其设计要点在于门控默认关闭：自部署与 PyPI 用户不受任何限制，收费只收窄读取窗口，写入通道永远开放，开源版无功能付费墙。

Zep 的 Context MCP Server 按席位计费，席位随计划不同，自定义 OIDC 需企业计划；这反映了「把记忆开放给员工自带客户端」这一新场景的定价逻辑——它按「人」而非「调用量」计价。

三种结构对应三种假设：Mem0 假设价值在大客户的治理需求，Mnemosyne 假设价值在托管便利而非功能分层，Zep 假设价值在人均接入。没有哪种更正确，但它们会导向完全不同的产品路线。

六、信号五：中文与非英语场景的欠覆盖 ​

三个可观察的事实。

其一，主流基准的数据集以英语对话为主。LongMemEval 的 500 道题评测五项能力（信息抽取、多会话推理、时序推理、知识更新、拒答），其题目构造与语言强相关，直接翻译会改变难度分布。

其二，纯嵌入召回在中文专有名词上失准明显。产品型号、人名、项目代号这类 token 在嵌入空间中与常见词的区分度不足，而 BM25 类的词法信号恰好在此处精度更高。工程上的应对是把词法信号作为一等公民而非兜底：Mnemosyne 采用 Bigram 分词 + FTS5 + 内置同义词词典，并在嵌入服务不可用时保留 BM25 回退。

其三，中文的时间表达（「上周三」「去年底」「这季度」）需要专门的相对时间解析，否则「何时发生」这一维度直接失效，而双时间轴正是冲突裁决的基础。

这三点的共同结论是：中文场景不能靠「换一个多语言嵌入模型」解决，它需要检索管线层面的适配。目前公开的针对性对照实验很少，这是本书认为最值得补的一块空白。

七、本章结论 ​

五组信号指向同一个判断：2026 年记忆系统的竞争已经从「能不能记住」转移到「记住的东西是否可被信任、可被解释、可被安全地遗忘」。

这个转移有三个具体含义。

对使用者：选型时应当把「证据」而非「功能」作为主要判据。能提供可复算基准、可定位审计、可预览删除的系统，即使功能列表更短，长期风险也更低。

对建设者：基础范式已经趋同，继续在「我们也支持 ADD-only」上做差异化没有意义。真正的空间在三个方向——冲突裁决的准确率、删除的可验证性、经验抽象的质量度量。

对研究者：工业界最缺的不是新算法，而是可复现的失败案例集与跨系统的成本-质量曲线。这两样东西的价值会超过任何单个系统的 headline 分数。

接下来的架构篇会把这三条判断落成具体的责任划分与投入刻度。
