信任中心

安全模型、合规映射（HIPAA / 等保 / GDPR / PIPL）与 SHA-256 哈希链审计。

没有东西离开这台机器，所以信任边界就是文件系统。我们要声明的不是 Mnemosyne OS 持有某张证书 —— 而是它的行为可以被审查，下面每一条都能对应到你可以读的代码。

信任边界就是一个文件

链路里没有任何托管控制面。记忆是磁盘上的一个 SQLite 文件，账本在同一个数据库里，核心不导入 Python 标准库之外的任何东西。删掉那个文件就是一次完整、可审计的删除 —— 没有副本需要追。

  • 核心零第三方依赖。 install_requires 是空列表，并且会一直保持。
  • 无遥测。 没有需要关闭的东西，因为什么都没采集。
  • 默认离线。 向量层是可选的，断网时软退回本地 FTS5 索引。

篡改从一开始就可被发现

每次写入都串进 SHA-256 账本。校验不只告诉你"有东西被改过"，而是指出是哪一条记录被改 —— 这让篡改从"可否认"变成"可检测"。

mnemosyne --dir ./mem verify-integrity --json
# { "chain_valid": true, "records_checked": 10287 }

mnemosyne --dir ./mem ledger-audit "<memory_id>"
# 围绕某一条记录走一遍链

安全公证

写入前的检查阶段，SDK、命令行、MCP 与批量路径全都会走。

  • 凭据检测 —— API 密钥、密码、卡号在落库前就被识别。
  • 不可见 Unicode 检测 —— 零宽字符与双向控制符会被暴露出来，而不是被存下去。
  • HTML 注入检测 —— 标记会被标记出来，而不是原样持久化、等着下游渲染器去执行。
  • 字段级脱敏 —— 敏感字段在写入时打码，公证的原始判断保留在 meta 里而不是被丢弃。

合规

HIPAA、等保、GDPR 与 PIPL 的映射与账本一起维护，因此合规审查可以用证据回答，而不是填一份问卷。
