MCP 集成

把 Mnemosyne OS 接入 Claude Desktop、Cursor 等 MCP 客户端，52 个工具开箱可用。

MCP 服务端跑 stdio JSON-RPC，支持可选的令牌鉴权与多租户命名空间。三十一个工具、一条命令，没有需要长期维护的适配层。

启动服务端

桌面客户端走 stdio，跑在端口后面的一切走 Streamable HTTP。

# stdio —— 每个桌面客户端都认的形状
export MNEMOSYNE_MCP_TOKEN="your-secret-token"   # 可选，但建议开启
python -m mnemosyne.webui.mcp_server --brain-dir ./mem --namespace default

# 客户端一侧就是三个键加一条命令
{
"mcpServers": {
"mnemosyne": {
"command": "python",
"args": ["-m", "mnemosyne.webui.mcp_server",
"--brain-dir", "./mem", "--namespace", "default"],
"env": { "MNEMOSYNE_MCP_TOKEN": "your-secret-token" }
}
}
}

租户隔离是物理的

令牌映射命名空间，命名空间映射各自的存储。这不是在一张共享表上做权限过滤。

  • 一把令牌，一个命名空间。 服务端从令牌解析命名空间，客户端无法索取别人的。
  • 每个命名空间一个独立 SQLite 文件与独立向量集合。
  • 每个命名空间一条独立的哈希链审计轨迹，审查一个租户的账本不需要暴露另一个。
  • list_projects 只枚举这把令牌有权看到的命名空间。

默认的安全姿态

不配置也合理，配置了可审查。

  • 连接时做令牌鉴权；纯本地 stdio 用途可以不开。
  • 每次写入前都过安全公证：凭据检测、不可见 Unicode 检测、HTML 注入检测，然后做字段级脱敏。
  • 显式传入的置信度不会被覆盖。 调用方写入 confidence 0，得到的是撤回，而不是被静默改写。
  • 默认软遗忘。 confidence 归零、记录标记为 deleted，审计链保持完整；物理删除需要显式 evict=true。

一个已知边界，如实说明：与库内任何内容都没有词面或标签锚点的纯改写问句，可能落到相关性下限之下并返回空。这是刻意的取舍 —— 对智能体而言，空结果比五条无关记忆安全得多。重排插件存在的意义就是补上剩下的缺口。
